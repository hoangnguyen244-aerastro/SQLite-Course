# Тема 7 — Практическая часть: «Простой склад» (b16)

**Статус:** реализация по подтверждённому комментарию из учебного примера `b16/main.c`, Урок 7.3:
> Задание — добавить обработку всех полей и сделать формы для расходных накладных.

Полное содержание `template/Tema_7.pdf` пока недоступно для просмотра через GitHub; поэтому это **реализация подтвержденной части**, не гарантия выполнения всех заданий PDF.

## Реализовано на отдельной копии b16
1. `rash.c`: правильный Тип=0 для расходных накладных (как в представлении БД), открытие и удаление.
2. `rash_editor.c`: окно редактирования документа; Номер, Дата, Поставщик, Покупатель; строки по товарам, количество расхода, сумма.
3. Атомарная выдача товара: проверка остатков; SQL-транзакция `BEGIN IMMEDIATE` / `COMMIT` / `ROLLBACK`; нельзя выдать больше остатков.
4. При удалении строки или документа остаток товара восстанавливается.
5. `tovar_extra.c`: дополнительный диалог для полей «Цена закупки», «Цена розничная», «Место хранения», «Стеллаж», «Полка», встроенный кнопкой в окно товара.
6. `b16.cbp`: подключены новые файлы и скорректирован Windows linker.

## Инструкция Code::Blocks 17.12 (русский интерфейс)
1. В GitHub Desktop: Fetch/Pull ветку `review/remaining-coursework-2026-11-23`.
2. Создать `C:\Work\Tema7_b1\b16\` и **полностью** скопировать туда содержимое `Tema7_b1_configured\b16`.
3. В Code::Blocks открыть `b16.cbp`; выбрать **Сборка → Очистить**, затем **Сборка → Пересобрать**; сохранить снимок ошибок/предупреждений.
4. При 0 errors запустить F9. Нажать «Товары», открыть товар, найти кнопку «Цена и место хранения» и заполнить розничную цену, количество и место хранения.
5. В главном окне открыть «Расходные накладные», выбрать «Добавить»: должна открыться форма; заполнить номер/дату/покупателя/поставщика. Добавить строку расхода и проверить, что остаток уменьшился.
6. Проверить запрет расхода сверх остатка; удалить строку и убедиться, что остаток вернулся; закрыть и повторно открыть документ.
7. Проверить сохранённые данные в SQLiteStudio. Все эксперименты выполнять на отдельной копии `b16.db`, не на примерах преподавателя.
8. При наличии физических принтеров необязательно печатать — задание о складских формах не требует изобретать печать.

## SQL для контроля
```sql
SELECT "Код накладной", Номер, Дата, Поставщик, Покупатель, Сумма
FROM "Расходные накладные" ORDER BY "Код накладной" DESC;

SELECT s."Код строки накладной", s."Код накладной", t.Товар,
       s.Расход, t.Количество, t."Цена розничная"
FROM "Строки накладной" s JOIN Товары t
ON t."Код товара"=s."Код товара"
WHERE s.Расход > 0
ORDER BY s."Код накладной";

SELECT "Код товара", Товар, Количество, "Цена закупки",
       "Цена розничная", "Место хранения", Стеллаж, Полка FROM Товары;
```

## Честные ограничения
- Windows-сборка GTK не проверена дистанционно: возможны несовместимости в библиотеке Code::Blocks.
- Окончательный PDF/DOCX со снимками не составлен, пока не получены результаты реального запуска.
- Исходная СУБД содержит представление «Расходные накладные» для `Тип=0`; в оригинальном исходнике обработчик вставлял `Тип=-1`, что исправлено.
- Цены в итогах берутся из текущей карточки товара; историческая цена не фиксируется в строке документа. Для бухгалтерской точности это отдельное улучшение.
